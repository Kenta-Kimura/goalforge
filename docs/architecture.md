# アーキテクチャ

## 目的

GoalForgeは、学習対象の構造と学習の事実を分離し、同じ教材を継続して改善・分析できる学習管理アプリです。設計では保守性、拡張性、一貫性を優先します。

## 責務分離

### 教材管理: マスターデータ

教材管理は「何を学ぶか」の唯一のマスターです。

- 教材
- セクション
- 問題

教材名、問題文、配点、評価形式など、学習対象そのものの構造を管理します。解答結果や周回は教材管理へ保持しません。

#### 教材削除時のライフサイクル

教材削除では`Material`を削除の起点とします。関連するセクション、問題、解答履歴、復習状態、周回、周回対象は、SQLiteの外部キー`ON DELETE CASCADE`により同じ教材の範囲で削除されます。他の教材のデータには影響しません。

アプリが関連テーブルを個別に順番削除する設計ではありません。`Material`の削除と関連データのカスケード削除は1トランザクション内の原子的な操作として扱い、すべて成功するか、失敗時は削除前の状態へ戻ります。アプリケーションはCASCADEの物理的な実行順序には依存せず、トランザクション完了後の整合した状態だけを扱います。

### 演習: 学習データ

演習は「どのように取り組み、何が起きたか」を記録します。

- 解答履歴
- 正誤・部分点
- 確信度
- 周回と周回対象
- 復習状態

解答時点の満点は履歴にスナップショットとして保存し、後から教材の既定配点を変更しても過去の結果が変わらないようにします。

### ダッシュボード: 統計・分析

ダッシュボードはマスターと学習履歴を読み取り、次を算出・可視化します。

- 正答率
- 学習時間
- 学習量や成績の推移
- 教材別・期間別の可視化

集計結果は可能な限り履歴から導出し、同じ意味の永続データを複数箇所に持たせません。学習時間の履歴化と詳細な推移表示は今後拡張します。

## 教材を複製しない

履歴や周回を作成するたびに教材・セクション・問題を複製しません。教材マスターは一つに保ち、演習側がそのIDを参照します。

周回開始時には「その周回で対象だった問題」の関連だけを`round_target_problems`へ保存します。これにより、後で復習状態が変わっても過去の周回対象を再現でき、問題マスター自体の重複は避けられます。

## 実装レイヤー

- `src/`: React UI、画面状態、フロントエンドのドメインロジック
- `src/questionBank/`: 教材管理・演習の型、サービス、SQLite呼び出し
- `src-tauri/src/`: Tauriコマンド、トランザクション、SQLiteアクセス
- `src-tauri/migrations/`: 順次適用するSQLite Migration
- `scripts/`: ドメインロジックと入力検証のテスト

UIからSQLiteを直接操作せず、フロントエンドのサービスとTauriコマンドを境界にします。

## データの正本

デスクトップ版ではSQLiteだけを永続データの正本とします。教材・問題は正規化テーブル、解答履歴は`problem_attempts`、目標や学習計画などのアプリ状態は`app_state`へ保存します。LocalStorageは旧Web版データの初回移行元に限定し、現在のバックアップ対象にはしません。AnkiConnectが利用できない場合は、SQLiteに保存した最終同期データを表示できる構成を維持します。

## バックアップと復元

完全バックアップの単位はSQLiteデータベース全体です。AppStateだけを対象にしたJSON Exportは行いません。旧バックアップとの互換性のためJSON Importだけを残し、教材・問題・解答履歴などSQLite固有データは変更しません。SQLite Online Backup APIにより、WAL利用中も単一の一貫したバックアップファイルを作成します。

復元は次の境界で行います。

1. SQLite形式と`PRAGMA integrity_check`を確認する
2. GoalForgeの必須テーブルと外部キー整合性を確認する
3. スキーマバージョンを確認し、古いDBへ現在のMigrationを適用する
4. 新しすぎるDBは現在のアプリでは復元しない
5. 復元対象の件数を利用者へ提示する
6. 現在DBの完全バックアップを自動作成する
7. 検証済みDBをOnline Backup APIで現在の接続へ復元する
8. SQLite接続設定を再適用し、画面状態を再読込する

復元用DBの検証とMigrationは一時DB上で完了させ、現在DBへ未検証データを直接書き込みません。復元処理が失敗した場合は、自動バックアップから現在DBを戻せる構成にします。
