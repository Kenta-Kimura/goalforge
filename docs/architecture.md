# アーキテクチャ

## 目的

GoalForgeは、学習対象の構造と学習の事実を分離し、同じ教材を継続して改善・分析できる学習管理アプリです。設計では保守性、拡張性、一貫性を優先します。

## 責務分離

### 教材管理: マスターデータ

教材管理は「何を学ぶか」の唯一のマスターです。

- 教材
- セクション
- 問題

教材名、問題文、配点、評価形式など、学習対象そのものの構造を管理します。解答結果や周回は教材管理へ保持しません。

### 演習: 学習データ

演習は「どのように取り組み、何が起きたか」を記録します。

- 解答履歴
- 正誤・部分点
- 確信度
- 周回と周回対象
- 復習状態

解答時点の満点は履歴にスナップショットとして保存し、後から教材の既定配点を変更しても過去の結果が変わらないようにします。

### ダッシュボード: 統計・分析

ダッシュボードはマスターと学習履歴を読み取り、次を算出・可視化します。

- 正答率
- 学習時間
- 学習量や成績の推移
- 教材別・期間別の可視化

集計結果は可能な限り履歴から導出し、同じ意味の永続データを複数箇所に持たせません。学習時間の履歴化と詳細な推移表示は今後拡張します。

## 教材を複製しない

履歴や周回を作成するたびに教材・セクション・問題を複製しません。教材マスターは一つに保ち、演習側がそのIDを参照します。

周回開始時には「その周回で対象だった問題」の関連だけを`round_target_problems`へ保存します。これにより、後で復習状態が変わっても過去の周回対象を再現でき、問題マスター自体の重複は避けられます。

## 実装レイヤー

- `src/`: React UI、画面状態、フロントエンドのドメインロジック
- `src/questionBank/`: 教材管理・演習の型、サービス、SQLite呼び出し
- `src-tauri/src/`: Tauriコマンド、トランザクション、SQLiteアクセス
- `src-tauri/migrations/`: 順次適用するSQLite Migration
- `scripts/`: ドメインロジックと入力検証のテスト

UIからSQLiteを直接操作せず、フロントエンドのサービスとTauriコマンドを境界にします。

## データの正本

デスクトップ版の学習データはSQLiteを正本とします。LocalStorageは、旧Web版データの初回移行元と、失われても復元可能なUI設定に限定します。AnkiConnectが利用できない場合は、SQLiteに保存した最終同期データを表示できる構成を維持します。
